# Bộ Ca Kiểm Thử Chi Tiết (Test Cases Specification)
## Phân hệ Quản Trị, Kiểm Duyệt & Báo Cáo — TV5

> **Trạng thái thực thi:** Toàn bộ test case dưới đây được soạn thảo trong giai đoạn **Tuần 1 (Thiết kế)** và đang ở trạng thái **`Chưa thực thi (Planned)`**. Các bài kiểm thử tự động (Unit Test / Integration Test) sẽ được lập trình và chạy trong Tuần 2 và Tuần 3 khi mã nguồn phân hệ hoàn thành.

|---|---|---|---|---|---|:---:|

| **TC-REP-09** | Xử lý đồng thời tiếp nhận Report (Claim lock) | Có 1 report `OPEN`. Hai Mod cùng bấm "Tiếp nhận". | 1. Mod 1 gọi `/claim` thành công.<br>2. ## 3. Ca kiểm thử Nhật ký kiểm toán (Audit Log Test Cases)

| Mã ca kiểm thử | Tên ca kiểm thử | Điều kiện tiên quyết | Các bước thực hiện | Dữ liệu kiểm thử | Kết quả mong đợi | Trạng thái |
|---|---|---|---|---|---|:---:|
| **TC-AUD-01** | Tạo Audit Log khi hành động quản trị thành công | User có quyền Admin/Mod. | 1. Mod thực hiện ẩn một Review.<br>2. Query bảng `audit_logs` kiểm tra bản ghi mới nhất. | Hành động: `MODERATE_REVIEW_HIDE`. | - Có 1 bản ghi mới trong `audit_logs`.<br>- `action` = `'MODERATE_REVIEW_HIDE'`.<br>- `actor_id` = ID của Mod. | Chưa thực thi (Planned) |
| **TC-AUD-02** | Kiểm tra tính đầy đủ của snapshot before/after | Place được cập nhật thông tin bởi Content Admin. | 1. Admin đổi tên Place từ "Cầu Rồng Cũ" thành "Cầu Rồng Đà Nẵng".<br>2. Kiểm tra `before_state` và `after_state` trong audit log. | `name`: "Cầu Rồng Đà Nẵng". | - `before_state->>'name'` chứa "Cầu Rồng Cũ".<br>- `after_state->>'name'` chứa "Cầu Rồng Đà Nẵng". | Chưa thực thi (Planned) |
| **TC-AUD-03** | Thao tác thất bại không tạo audit log thành công giả | Request bị chặn bởi lỗi validation hoặc phân quyền. | 1. USER thường gọi API khóa tài khoản (bị 403).<br>2. Kiểm tra DB `audit_logs`. | Request lỗi 403. | - Không có bản ghi nào được tạo trong `audit_logs` thể hiện hành động thành công. | Chưa thực thi (Planned) |
| **TC-AUD-04** | Ngăn chặn sửa/xóa Audit Log qua API | Bảng `audit_logs` đã có dữ liệu. | 1. Cố gắng gọi HTTP `DELETE /api/v1/admin/audit-logs/{id}` hoặc `PUT`. | ID của log hiện có. | - API trả về `405 Method Not Allowed` hoặc `404 Not Found`. Không có endpoint sửa/xóa audit log. | Chưa thực thi (Planned) |
| **TC-AUD-05** | Audit Log không chứa mật khẩu hoặc JWT token | Admin thực hiện cập nhật người dùng. | 1. Admin reset mật khẩu hoặc cập nhật tài khoản.<br>2. Kiểm tra nội dung JSON trong `before_state` và `after_state`. | Thao tác cập nhật user. | - Tuyệt đối không chứa các key `password`, `password_hash`, `token`, `secret` trong JSON (BR-166). | Chưa thực thi (Planned) |
| **TC-AUD-06** | Audit Log không lưu tọa độ GPS thời gian thực | User gửi check-in hoặc thao tác vị trí. | 1. Kiểm tra log của các thao tác liên quan tới vị trí. | Dữ liệu có tọa độ. | - Chỉ lưu `place_id` hoặc khoảng cách tương đối, không lưu lịch sử tọa độ chính xác thời gian thực (BR-09, BR-10). | Chưa thực thi (Planned) |

## 4. Ca kiểm thử Quản trị & Phân quyền bảo mật (Admin & Security Test Cases)

| Mã ca kiểm thử | Tên ca kiểm thử | Điều kiện tiên quyết | Các bước thực hiện | Dữ liệu kiểm thử | Kết quả mong đợi | Trạng thái |
|---|---|---|---|---|---|:---:|
| **TC-SEC-01** | Chưa đăng nhập truy cập API Quản trị | Khách vãng lai (`GUEST`). Không có Header Authorization. | 1. Gửi request `GET /api/v1/admin/moderation/queue`. | Không có token. | - Trả về `401 Unauthorized`. | Chưa thực thi (Planned) |
| **TC-SEC-02** | User thường truy cập API Admin | Đăng nhập tài khoản có role `USER`. | 1. Gửi request `GET /api/v1/admin/reports`. | Token: Bearer JWT của USER. | - Trả về `403 Forbidden`. | Chưa thực thi (Planned) |
| **TC-SEC-03** | Content Admin gọi API của System Admin | Đăng nhập với role `CONTENT_ADMIN`. | 1. Cố gắng gọi `POST /api/v1/admin/system/users/{id}/lock` (chỉ dành cho System Admin). | Token: CONTENT_ADMIN. | - Trả về `403 Forbidden`. | Chưa thực thi (Planned) |
| **TC-SEC-04** | Khóa tài khoản và thu hồi quyền truy cập | System Admin khóa 1 tài khoản vi phạm. | 1. System Admin gọi `POST /api/v1/admin/users/{id}/lock` kèm lý do.<br>2. Tài khoản bị khóa dùng token cũ để gọi API. | `reason`: "Vi phạm điều khoản cộng đồng nhiều lần". | - Trả về `200 OK`. Trạng thái user chuyển thành `LOCKED`.<br>- Khi user gọi API tiếp theo -> Nhận `403 Forbidden: Tài khoản đã bị khóa`. | Chưa thực thi (Planned) |
| **TC-SEC-05** | Tài khoản LOCKED cố gắng đăng nhập mới | Tài khoản đang có `status = 'LOCKED'`. | 1. Gọi `POST /api/v1/auth/login` với email và mật khẩu đúng của tài khoản bị khóa. | Email & Password của user bị khóa. | - Trả về `403 Forbidden` hoặc `401 Unauthorized`.<br>- Thông báo lỗi rõ ràng: "Tài khoản của bạn đã bị khóa. Vui lòng liên hệ hỗ trợ" (BR-06). | Chưa thực thi (Planned) |
| **TC-SEC-06** | Chống SQL Injection trong tham số lọc hàng đợi | Đăng nhập với role Admin. | 1. Gọi `GET /api/v1/admin/reports?status=' OR 1=1 --`. | Payload SQL Injection. | - Trả về `400 Bad Request` do validation enum `status` hoặc ORM parameterize an toàn. Không rò rỉ dữ liệu ngoài phạm vi. | Chưa thực thi (Planned) |
| **TC-SEC-07** | Chống XSS trong trường lý do kiểm duyệt/báo cáo | Gửi payload chứa mã script độc hại. | 1. Gửi báo cáo với `description`: `<script>alert('XSS')</script>`.<br>2. Admin xem chi tiết báo cáo trên web. | Payload XSS. | - Nội dung được sanitize hoặc encode an toàn khi lưu trữ và hiển thị, không thực thi script trên trình duyệt. | Chưa thực thi (Planned) |
| **TC-SEC-08** | System Admin không có API đọc dữ liệu cá nhân nhạy cảm | Đăng nhập với role `SYSTEM_ADMIN`. | 1. Thử gọi API đọc chi tiết lịch trình cá nhân hoặc collection riêng tư của người dùng khác. | Token: SYSTEM_ADMIN. | - Bị từ chối `403 Forbidden` hoặc `404 Not Found` (Tuân thủ nguyên tắc quyền riêng tư BR-170). | Chưa thực thi (Planned) |
